\section{Balance de Carga Usando Grafos Basados en Conjuntos}


\begin{frame}{Motivación}
  Los métodos de particionamiento actuales son sensibles al tamaño del grafo.\pause

  Modelos de gran escala $\to$ grafos computacionales de gran tamaño.\pause

  Queremos representar el grafo computacional en forma compacta y particionarlo
  sin necesidad de expandir.\pause

  La implementación del modelo tiene una estructura compacta, ¿podemos aprovecharla?\pause

  Presentamos un algoritmo de Balance de Carga usando Grafos Basados en Conjuntos.
\end{frame}


\begin{frame}{Formato de Entrada}

 Si definimos la ocurrencia de una variable en una expresión dada como:\pause

\begin{small}
    \begin{algorithm}[H]
        \begin{algorithmic}\caption{Tipo Var}
            \State \textbf{Var}: \{
                \State $\text{id}: \text{string}$ 
                \State $\text{cost}: \text{int}$
                \State $\text{exp}: (a,b)$ donde $a, b \in N^0$ y estos representan constante y
                pendiente en la expresión $a \times i + b$
                \State $\text{def}: \{ n_1 , \ldots , n_k \}$ donde $n_i$ es el id de un conjunto
                de nodos donde se calcula la variable. Es decir, aparece en el lado izquierdo
                de la ecuación.
            \State \} 
        \end{algorithmic}
    \end{algorithm}
\end{small}
\end{frame}


\begin{frame}{Formato de Entrada}

  Un nodo individual que representa una unidad de cálculo en el modelo puede ser 
definido así:
\pause

\begin{small}
    \begin{algorithm}[H]
        \begin{algorithmic}\caption{Tipo Node}
            \State \textbf{Node}: \{
                \State $\text{id: string}$
                \State $\text{weight: int}$
                \State $\text{interval:} [1,\dots,M]$
                \State $\text{lhs:}  \{ L_1, \dots, L_k \}$ donde $L_i$ tiene tipo \textbf{Var}
                \State $\text{rhs} :  \{ R_1, \dots, R_g \}$ donde $R_i$ tiene tipo \textbf{Var}
            \State \}
        \end{algorithmic}
    \end{algorithm}
\end{small}

Y finalmente podemos definir: $\text{Nodes} : \{ I_1, \dots, I_m\}$ con $I_j$
del tipo $\text{Node}$ como entrada del algoritmo de particionado.
\end{frame}

\begin{frame}{Particionamiento Inicial}

Debemos hacer un particionamiento inicial, para luego mejorarlo y obtener un
particionamiento de calidad.\pause

El nodo con más cantidad de aristas se elige como nodo raíz.\pause

Se recorre el grafo por anchura.\pause

Usamos dos estrategias para el armado de las particiones iniciales:\pause

\begin{itemize}
    \item \textbf{Estrategia Greedy}, a medida que se recorre el grafo, se 
    agregarán todos los elementos a una partición hasta que esté 
    completa.\pause

    \item \textbf{Estrategia Distributiva}, cada intervalo se parte en $P$
    partes iguales y se reparten una parte para cada partición.
\end{itemize}

\end{frame}

\begin{frame}{Refinamiento}

Una vez obtenidas las particiones iniciales, entramos en la etapa de
refinamiento, etapa en la cual buscamos disminuir la comunicación entre
las mismas, sin desbalancear.
\pause

Buscamos disminuir el $edgeCut$.
\pause

Dada una partición $\mathcal{C}$ en $P$ particiones disjuntas
$\mathcal{V} = (\mathcal{C}_1 \cup \ldots \cup \mathcal{C}_p)$,
\pause

\begin{equation*}
\begin{aligned}
    cost(\mathcal{C}) = edgeCut(\mathcal{C}) =  \sum_{\mathcal{C}_i
    , \mathcal{C}_j} \{ w(u, v) | u \in \mathcal{C}_i, v \in 
    \mathcal{C}_j, i \neq j \}\text{{\color{black},}}
\end{aligned}
\end{equation*}
\pause

\begin{equation*}
\begin{aligned}
    & \underset{\text{todo } \mathcal{C}}{\text{minimizar }} edgeCut(\mathcal{C})\\
    & \text{{\color{black}sujeto a} } \sum_{u \in \mathcal{C}_i} l(u) = \frac{\sum_{v \in \mathcal{V}}}
    {P}, \forall i\text{{\color{black}.}}
\end{aligned}
\end{equation*}

\end{frame}


\begin{frame}{Kernighan-Lin}

Sea $S$ un conjunto de $2n$ puntos, con una matriz de costo asociada 
$C = (c_{ij})$, $i, \text{ } j = 1, \ldots, 2n$.
\pause

Queremos partir $S$ en dos conjuntos $A$ y $B$, cada una con $n$ puntos,
tales que el ``costo externo'' $T = \sum_{A \times B} c_{ab}$ se minimice.
\pause

Definamos para cada $a \in A$, un \textit{costo externo} (EC) $E_a$

\begin{equation*}
    E_a = \sum_{y \in B} c_{ay}
\end{equation*}
\pause

y un \textit{costo interno} (IC) $I_a$

\begin{equation*}
    I_a = \sum_{x \in A} c_{ax}
\end{equation*}
\pause

Análogamente, definimos 
$E_b$, $I_b$ para cada $b \in B$.

\end{frame}


\begin{frame}{Kernighan-Lin}

Sea

\begin{equation*}
D_x = E_x - I_x \text{ para todo } x \in S; 
\end{equation*}

$D_x$ es la diferencia entre costo externo e interno.
\pause

Considerando cualquier $a \in A$, $b \in B$. Si $a$ y $b$ son intercambiados, la \textit{ganancia}
(esto es, la reducción del costo) es precisamente.
\begin{equation*}
D_a + D_b - 2c_{ab}    
\end{equation*}
\pause

Este proceso se repite y se acumulan las ganancias parciales.
Una vez culminado, se elige el intercambio con ganancia máxima.

\end{frame}


\begin{frame}{Kernighan-Lin}

  Fase de optimización para dos particiones:
  \pause

  \begin{itemize}
    \item Computar $D$ para todos los elementos de $S$.
    \pause

    \item Elegir $a_i \in A$, $b_j \in B$ tal que:
          $g_1 = D_{ai} + D_{bj} - 2c_{c_{a_ib_j}}$ es máxima.
    \pause

    \item Recalcular $D$ para los elementos de $A - \{a_i\}$ y $B - \{b+j\}$
    \pause

    \item Repetir el paso dos, eligiendo un par $a'_2$, $b'_2$ tal que:
          $g_2 = D_{a'_2} + D_{b'_2} - 2c_{a'_2b'_2}$ es máxima.
    \pause

    \item Repetir el proceso hasta que se hayan agostado todos los nodos.
  \end{itemize}
  \pause

  Si $X = a'_1, a'_2, \cdots, a'_k$, $Y = b'_1, b'_2, \ldots, b'_k$, entonces
  la disminución en costo al intercambiar $X$ e $Y$ es precisamiente
  $g_1 + g_2 + \cdots + g_k$.
  \pause

  Elegir $k$ que maximice la suma parcial $\sum_{i=1}^k g_i = G$.
  \pause

  Si $G > 0$, habrá una reducción al intercambiar $X$ e $Y$.
\end{frame}

\begin{frame}[fragile]{Particionador SBG}

Cálculo de Costo Externo y Costo Interno.
\pause

Los argumentos de esta función son:
\pause

\begin{itemize}
    \item $S$, intervalo o conjunto sobre el cual calcular EC e IC.
    \pause

    \item $P$ que es la partición a la cual pertenece $S$.
    \pause

    \item $map_1$ y $map_2$ son los mapas del grafo.
\end{itemize}
\pause

\begin{small}
  \begin{algorithm}[H]
    \caption{Compute EC and IC}
    \begin{algorithmic}[1]
    \Function{compute\_EC\_IC}{S, P, map\_1, map\_2}
        \State $D \gets \text{map\_1.preImage}(S)$
        \State $I \gets \text{map\_2.image}(D)$
        \State $IC' \gets (P \cap I) / S$
        \State $IC \gets \text{map\_2.preImage}(IC') \cap D$
        \State $EC' \gets I / IC'$
        \State $EC \gets \text{map\_2.preImage}(EC') \cap D$
        \State \Return $(EC, IC)$
    \EndFunction
    \end{algorithmic}
    \end{algorithm}
\end{small}

\end{frame}


\begin{frame}{Particionador SBG}

$compute\_EC\_IC$ tiene un problema.
\pause
Si queremos particionar más de dos particiones, tomando de a dos,
incluiríamos en la EC de $S$ nodos fuera de $Q$.
\pause
Por eso implementamos la segunda versión.

Los argumentos son los mismos que la implementación anterior, sólo
se agrega $Q$, que es la otra partición que estamos refinando.

\begin{small}
  \begin{algorithm}[H]
    \begin{algorithmic}[1]\caption{Compute EC \& IC}
    \Function{compute\_EC\_IC}{$S, P, Q, map_1, map_2$}
        \State{$D = map_1.preImage(S)$}
        \State{$I = map_2.image(D)$}
        \State{$IC' = (P \cap I) / S$}
        \State{$IC = map_2.preImage(IC') \cap D$}
        \State{$EC' = (I / IC') \cap Q$}
        \State{$EC = map_2.preImage(EC') \cap D$}
        \State \Return $(EC,IC)$
    \EndFunction
    \end{algorithmic}
  \end{algorithm}
\end{small}

\end{frame}

\begin{frame}{KL-SBG para múltiples particiones}

  Sea $P = \{P_1, \ldots, P_n\}$ la partición inicial de nuestro grafo,
  queremos comprobar si podemos mejorarla.
  \pause

  \begin{itemize}
    \item Calular las posibles ganancias:
    $\forall i \in \{1, \ldots, n\} \forall j \in \{i+1, \ldots, n\}
          G_{ij} = KL-SBG(P_i, P_j)$
    \pause

    \item Tomamos la ganancia máxima $G_{ij}$. Si $G_{ij} > 0$, efectuamos el
    intercambio.
    \pause

    \begin{itemize}
      \item Sean $X \subset P_i$, $Y \subset P_j$ los conjuntos cuyo intercambio
      genera ganancia $G_{ij}$, entonces:\\
        $P'_i = P_i \setminus X \cup Y$\\
        $P'_j = P_j \setminus Y \cup X$.
    \end{itemize}
    \pause

    \item Repetir desde el primer paso con las particiones $i$ y $j$ actualizadas
    hasta que no haya ganancias positivas.
  \end{itemize}

\end{frame}


\begin{frame}{KL-SBG para múltiples particiones}

  Algunas mejoras:
  \pause

  \begin{itemize}
    \item Aplicar más de un intercambio cuando sea posible sigiuendo la siguiente regla:
    \pause

    \begin{itemize}
      \item Sea $G = \{G_{xy}, \ldots\}$ el conjunto de ganancias positivas luego de
      aplicar $KL-SBG$ a las particiones.
      \pause

      \item Sea $G_{ij}$ la ganancia máxima, realizar los intercambios para $P_i$ y $P_j$.
      \pause

      \item Descartar todas las ganancias que involucren a $P_i$ y $P_j$,
      $G' = G \setminus G_{xy}$ tal que $x \in \{i, j\} \lor y \in \{i,j\}$.
      \pause

      \item Repetir hasta que $G' = \emptyset$.
      \pause
    \end{itemize}

  \item Aplicar $KL-SBG$ entre dos particiones $P_i$, $P_j$ si existe comunicación
  entre las mismas, es decir, si $edgeCut(P_i, P_j) > 0$.
  \pause

  \item Las ejecuciones de $KL-SBG$ se ejecutan en paralelo.
  \end{itemize}

\end{frame}
